How to Build Fully Responsive Websites

Nitin Khalasi · January 2026 · 5 min read

"Responsive" gets treated like a checkbox — add a few media queries, shrink the font size on mobile, ship it. In practice, a layout that actually holds up across screen sizes needs a plan before you write any CSS. Here's the approach I use on client projects.

1. Start from a fluid grid, not fixed breakpoints

CSS Grid and Flexbox let you describe how space should be shared, not just how it should be split at specific widths. A row built with display: flex; flex-wrap: wrap; and percentage or minmax() based widths will often adapt on its own, long before you need a media query to rescue it.

2. Use media queries to adjust the plan, not patch it

Breakpoints should follow your content, not a list of device widths. I usually check where a layout starts to feel cramped and set a breakpoint there instead of guessing at 768px or 1024px because "that's standard."

  • Design mobile-first, then add complexity as space allows
  • Keep touch targets at least 44px tall on small screens
  • Test real content, not lorem ipsum — long names and titles break layouts differently

3. Images and type need to scale too

A responsive layout with a fixed 40px heading on mobile still feels broken. I lean on clamp() for type sizing and set images to max-width: 100%; height: auto; by default so nothing overflows its container.

4. Test on the devices your users actually have

Browser dev tools are a good first pass, but they don't catch everything. Before I hand a project off, I check it on at least one real phone and one real tablet.
